# Feature Specification: Carousel Interaction Motion

**Feature Branch**: Not created; no branch hook configured. Feature identifier: `003-carousel-interaction-motion`.

**Created**: 2026-10-28

**Status**: Original motion behavior implemented and browser-verified on 2026-10-29. The 2026-10-30 carousel layout and startup-loading amendment is implemented; see [quickstart.md](quickstart.md) for observed verification and remaining limits.

**Input**: User description: "i want a turntable rotation for the models, while keeping the dragging to rotate working, but on release return to the last rotation and continue the turntable" and "in pressing next or previous, moves the model left or right and scaling small to look like an actual carousel instead of replacing the model entirely." The owner selected Option A: implement description/active-mode-arrow/pointer-outline refinements directly, and specify only these two motion changes as a new feature.

## Clarifications

### Session 2026-10-28

- Q: After releasing a drag, which pose should the model ease back to before continuing its turntable rotation? → A: **Pre-drag turntable pose**. Pause the turntable during dragging, return both axes to the pose it had when the drag began, then resume spinning. Do not keep the dragged heading or tilt as the new turntable baseline.

### Session 2026-10-29

- Q: How must the model, its title/description, and screen-reader position messages stay synchronized when selection details are delayed? → A: Hide selection details from both sight and assistive-technology reading as soon as navigation is accepted. Reveal only the current destination's matching details together with its centered model, and make its position message available once at that same settlement. Require an automated acceptance exercise with deliberately delayed destination details; do not prescribe how the application coordinates them.
- Q: What ends inspection and how is the return deadline measured with concurrent input, background suspension, and reduced motion? → A: Return starts only after all pointer/touch dragging and independently active keyboard inspection have ended. Releasing one does not end the other. Each uninterrupted return must finish within **0.5 seconds of visible viewing time**: add the observed return time before and after any hidden-tab, offscreen, or inactive-window pause, excluding the pause itself. Reduced motion restores the saved pose without an animated journey (**0 ms animated duration**) once inspection has fully ended; active manual control is never overridden.
- Q: When should the 0.5-second navigation deadline begin? → A: From **Next/Previous activation** to the centered model and matching visible details when no loading delay is deliberately introduced. Assess deliberately delayed-loading cases separately; a pause before visible movement is not excluded from the normal-navigation deadline.

### Session 2026-10-30

- Owner amendment: The Three.js canvas spans the full carousel width behind navigation controls. Start loading every catalog model at carousel startup without waiting for the others before showing the initial model when it is ready; one failure must not block other models. Hide nonparticipating models, including adjacent models at rest. Adopt Figma ProjectCarousel `39:205` while retaining existing motion, inspection, modes, metadata synchronization, accessibility, reduced motion, and responsive behavior.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Watch the turntable and temporarily inspect any side (Priority: P1)

A visitor sees the selected model slowly rotating without interaction. They can temporarily take control to inspect any side, then release it and watch it return smoothly to its pre-drag presentation before the turntable continues.

**Why this priority**: Automatic showcase motion must coexist with the existing full-turn inspection rather than fighting the visitor or making the manually tilted pose permanent.

**Independent Test**: Open one asymmetric, textured model, observe a complete turntable revolution, drag horizontally and vertically through full turns, and release at a visibly different tilt and heading. Compare the returned view with a reference view captured at inspection start and observe resumed rotation. Repeat with touch and keyboard, including simultaneous pointer/keyboard inspection, a hidden-tab pause during return, and reduced-motion restoration; time the visible return portions before and after a pause rather than including the hidden interval.

**Acceptance Scenarios**:

1. **Given** a ready, visible model and no reduced-motion preference, **When** it is not being inspected, **Then** it rotates continuously about its upright axis at a steady slow pace, showing front, sides, rear, and front without moving the showcase lights or changing its fitted size.
2. **Given** the turntable is rotating, **When** a primary drag begins, **Then** automatic rotation pauses at that pose and manual horizontal/vertical rotation follows the visitor through repeated full turns, including the top, underside, and inverted views without a stop.
3. **Given** a drag has changed both heading and tilt, **When** it ends and no independent keyboard inspection remains active, **Then** the model eases back to the saved pre-inspection pose on both axes within 0.5 seconds of visible viewing time, then resumes its previous turntable direction and speed. It does not jump upright, unwind a full revolution, or keep the dragged pose. If keyboard inspection remains active, ending the drag does not start return.
4. **Given** the model is returning from a drag, **When** another drag starts, **Then** the visitor immediately takes control from the currently visible pose; a later release still returns to the original turntable pose saved before that inspection sequence.
5. **Given** a keyboard-focused viewer, **When** a visitor uses arrow keys, **Then** they retain full-turn inspection and visible focus without navigation or a focus trap. Releasing an arrow key does not end keyboard inspection; moving keyboard focus away ends it and allows return only if no drag remains active. A click or tap used only for dragging does not start independent keyboard inspection, so ending that drag can start return without another click or a focus change.
6. **Given** a drag is canceled or the visitor switches away from the window, **When** that interaction ends, **Then** later pointer movement does not continue the abandoned drag. Canceling a drag does not end independent keyboard inspection; switching away ends all inspection. Return follows the same rule when viewing resumes, or restores without animation under reduced motion.
7. **Given** Clay, Rendered, or Wireframe is selected, **When** the visitor changes modes during spinning, dragging, or return, **Then** only appearance changes; the current pose and inspection/turntable progress are preserved.
8. **Given** a return is partly complete, **When** the tab is hidden for longer than 0.5 seconds and later shown, **Then** the model resumes from its last visible return pose without skipping ahead. The sum of the observed return portions before and after hiding is at most 0.5 seconds; the hidden interval is excluded.
9. **Given** reduced motion is active or becomes active after all inspection has ended, **When** the saved pose is restored, **Then** the next visible update shows that pose without intermediate animated return positions. If dragging or keyboard inspection is still active, the visitor keeps control until both have ended.

### User Story 2 - Browse models with directional carousel movement (Priority: P1)

A visitor presses the existing next or previous button and sees the model move sideways and become smaller as it leaves, while the adjacent model arrives from the opposite side and grows into the centered showcase position. The direction makes forward and backward browsing apparent instead of looking like an abrupt replacement.

**Why this priority**: Directional movement and scale are the requested carousel behavior; merely swapping a model or fading it does not communicate that relationship.

**Independent Test**: Supply three visually distinct test models. Use next/previous by pointer and keyboard, including both wrap boundaries, deliberately delayed destination details, an unavailable destination, and repeated navigation while loading. Observe direction, relative size, hidden selection details, matching model/detail settlement, and retained display mode at desktop and mobile widths. An automated acceptance exercise must also delay destination details and check the visible presentation and accessible position messages before and after settlement.

**Acceptance Scenarios**:

1. **Given** multiple models and a ready destination, **When** Next is activated, **Then** the outgoing model moves left and shrinks, while the incoming adjacent model arrives from the right and grows to its centered fitted size. Previous mirrors this choreography.
2. **Given** the last or first entry, **When** Next or Previous crosses the boundary, **Then** the same directional choreography occurs and the catalog wraps correctly; there is no backward-looking wrap shortcut.
3. **Given** an outgoing model with manual inspection in progress, **When** navigation is accepted, **Then** that inspection ends and cannot rotate the destination. The destination starts from its own fitted initial pose and begins its turntable after settling; the chosen display mode is retained.
4. **Given** a destination that is still loading, **When** navigation is accepted, **Then** a separate loading message names that destination and its title/description are hidden from sight and assistive-technology reading while the outgoing model may remain visible. No unloaded placeholder enters. The current destination's matching details appear together with its centered model, and only then is its new position message made available.
5. **Given** a destination that fails to load or render, **When** the failure becomes known, **Then** that destination is clearly identified as unavailable, motion does not continue indefinitely, and the visitor can navigate onward. The old model is not mislabeled as the successful destination.
6. **Given** multiple accepted navigation inputs during pending work, **When** loads and transitions finish, **Then** the settled model and all selection content match the final accepted request; stale results cannot replace it. Temporarily unavailable controls do not accumulate invisible extra activations.
7. **Given** zero or one catalog entry, **When** the page renders, **Then** next/previous remain disabled. An empty catalog has no viewer; a healthy single model still supports turntable, inspection, and display modes.
8. **Given** destination details are deliberately delayed for longer than the normal navigation deadline, **When** the destination model is otherwise available, **Then** its details remain hidden and successful settlement waits. No displayed image pairs a centered incoming model with the predecessor's readable details. When the delay ends, the correct model and details appear together and one current-selection position message becomes available; details from an abandoned selection never reappear or produce a new position message.
9. **Given** multiple catalog models, **When** the carousel starts, **Then** loading starts for every model without waiting for another model to finish, and the initial model is presented as soon as it is ready without waiting for the rest.
10. **Given** a model fails during startup loading, **When** a visitor views or navigates to another healthy model, **Then** that failure does not prevent the healthy model from loading or being presented. Selecting the failed model identifies it as unavailable and leaves navigation usable.
11. **Given** a settled selection, **When** the carousel is viewed at desktop or mobile width, **Then** only the selected model is visible; adjacent models do not appear at rest. During navigation, only the outgoing and incoming models participate in the existing transition.
12. **Given** the Figma ProjectCarousel layout, **When** the carousel is displayed, **Then** its Three.js canvas spans the full carousel width behind the navigation controls, which remain reachable and operable.

### Edge Cases

- Reduced motion disables automatic spin and animated sideways movement, size changes, and inspection return, but not manual rotation or adjacent selection. After all inspection ends, the saved pose appears on the next visible update without animated intermediate positions. Enabling reduced motion during a return does the same; enabling it during active inspection does not take control away from the visitor. Changing the preference takes effect without a reload.
- Hidden tabs, viewers scrolled out of sight, and inactive windows pause automatic motion. On return to viewing, the last visible pose continues without a jump or replay of the unseen interval. For inspection return, add only the visible viewing time before and after a pause; the pause neither consumes nor restarts the 0.5-second allowance. Leaving the viewer/page prevents abandoned gestures from affecting a later selection.
- Pressing or dragging near a full-revolution boundary returns by a short continuous path rather than visibly unwinding completed revolutions.
- Regrabbing interrupts return from the currently visible pose without changing the original saved showcase target. After all inspection ends again, a new return may take up to 0.5 seconds of visible viewing time. Repeated key presses or repeated endings of the same drag must not cause premature return or leave the model permanently under abandoned control.
- Interrupted return, navigation, resizing, and display-mode changes do not let an earlier gesture rotate a different model or leave the model stranded between positions or sizes.
- Models with different proportions or starting placements remain fully framed at rest without distortion or changed textures. Transitional movement stays within the viewing area and never creates page-level horizontal scrolling.
- Damaged or incomplete models, devices unable to show the model, and loss of the viewing surface retain readable unavailable messages and usable surrounding navigation. A different display mode must not turn a failed model into an apparently successful selection.
- Hover is not activation; pointer dragging has no viewer outline while keyboard focus stays visible. Active-mode arrows, custom descriptions, original background, and surrounding layout retain the direct refinements already implemented in feature 002.
- Accepted navigation hides the title/description before any new selection content can expose a mismatched identity. Hidden details must be unreadable both visually and through assistive technology. Loading/error messages remain separate, readable, and destination-named.
- Delayed details from an abandoned selection cannot reveal or announce that selection. Reduced motion and resuming viewing preserve the same matching-details rule without a fade effect. Failure identifies the unavailable destination with no old model underneath and no successful-settlement position message.
- An initial model that fails is identified as unavailable; other models continue loading and navigation to a healthy entry remains possible. A still-loading destination follows the existing loading and synchronization rules.
- Hiding a nonparticipating model prevents it from being drawn; loading or retaining it is not itself evidence of visibility or drawing.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: A ready, visible selected model MUST rotate automatically about its upright axis in all three display modes when motion is allowed and the visitor is not inspecting it. The pace MUST remain consistent on different displays; no automatic model selection is introduced.
- **FR-002**: Pointer and touch dragging MUST pause the turntable and allow repeated complete horizontal and vertical turns. After inspection ends, the model MUST return to the heading and tilt shown before that inspection began, not retain its manually changed pose. Dragging and independent keyboard inspection MUST coexist; clicking or tapping only to drag MUST NOT keep inspection active after the drag ends.
- **FR-003**: Return MUST start only after all dragging and independent keyboard inspection have ended. Ending one MUST NOT end the other. Each uninterrupted return MUST restore both saved axes within 0.5 seconds of visible viewing time, excluding hidden-tab, offscreen, and inactive-window intervals without restarting the allowance. Under reduced motion, the saved pose MUST appear on the next visible update without an animated return. Regrabbing MUST take control from the visible pose while retaining the original target; after all inspection ends again, a new return allowance applies.
- **FR-004**: Arrow keys MUST allow full-turn inspection without trapping keyboard focus. Keyboard inspection MUST pause automatic spin until keyboard focus leaves the viewer; releasing an individual arrow key MUST NOT end that inspection. Moving focus away MUST allow return only if no drag remains active. Pointer-only inspection MUST resume through the return without another click or focus change. Canceled interactions or switching away from the window MUST NOT leave an abandoned interaction controlling the model.
- **FR-005**: Next MUST move the outgoing model left while shrinking it and bring the next model from the right while growing it to its fitted size. Previous MUST mirror both movements. Wrapping MUST preserve the activated direction. Movement MUST affect the model presentation, not slide the title, mode controls, or entire page.
- **FR-006**: A transition MUST NOT present an unloaded destination as ready. While loading, the outgoing model MAY remain visible but its selection details MUST follow FR-012, and a separate loading message MUST name the requested destination. At successful settlement, the centered model, visible title/description, and accessible position message MUST identify the same selection. Failure MUST identify the unavailable destination, allow onward navigation, and never relabel the old model as a successful destination.
- **FR-007**: Selection MUST retain the chosen display mode but reset the destination to its own fitted initial pose. Rotation input MUST NOT affect a departing or not-yet-settled destination. Changing modes MUST preserve the current motion/inspection pose and progress.
- **FR-008**: Repeated accepted navigation MUST settle on the final requested catalog entry without a stale replacement or indefinite transition. Controls temporarily disabled for a transition MUST recover after completion/failure; a pending load MUST NOT permanently block browsing.
- **FR-009**: The viewer MUST respect changes to reduced-motion preferences by suppressing automatic rotation and animated selection/return while retaining manual rotation, readable selection state, and usable navigation. Hidden tabs, offscreen viewers, and inactive windows MUST pause automatic motion and resume without a jump.
- **FR-010**: At viewing widths of 375 and 1280 pixels, resting models MUST remain centered and fully visible as they rotate, controls MUST remain reachable, and transitions MUST NOT introduce page-level horizontal scrolling or move keyboard focus away from the activated control.
- **FR-011**: Existing empty/single-item navigation, automatically supplied model collections, optional descriptions, authored textures, display modes, visible keyboard focus, and background/page appearance MUST remain intact. Unreadable models MUST remain clearly unavailable rather than appearing successful in another mode. Abandoned interactions, failed selections, and leaving the page MUST NOT affect later selections.
- **FR-012**: On accepted navigation, the title and optional description MUST immediately become unreadable both visually and through assistive technology, before an incoming model can be confused with predecessor details. Only matching current-selection details MUST appear, together with that model's centered settlement in the same displayed image. A blank space or neutral loading message MAY occupy their place while waiting. Delayed details MUST postpone successful settlement; details from an abandoned selection MUST never reveal or settle it.
- **FR-013**: The accessible position message MUST identify each newly settled selection exactly once, only when its model and matching details appear together. Pending, abandoned, or failed selections MUST NOT produce new successful-selection position messages. Separate loading/error messages MAY describe their own states. This requirement concerns when the position message becomes available, not when assistive technology finishes speaking it.
- **FR-014**: The Three.js canvas MUST span the full carousel width behind the navigation controls. The carousel MUST adopt the layout and styling of Figma ProjectCarousel `39:205`, adapted responsively while preserving operable controls and existing accessibility.
- **FR-015**: At carousel startup, loading MUST start for every catalog model without waiting for another model's load to finish. The initial model MUST be presented as soon as it is ready and its matching details can settle, without waiting for other models. A model's load or rendering failure MUST NOT block other models from loading or being selected.
- **FR-016**: Nonparticipating models MUST be hidden and not drawn. At rest, only the selected model is visible; during a directional transition, the outgoing and incoming models may be visible. Adjacent models MUST NOT appear at rest.

### Key Entities

- **Showcase pose**: The selected model's heading and tilt immediately before inspection; the reference view to which it returns.
- **Inspection sequence**: Temporary visitor control of one selected model, from first inspection through any regrabs until its saved showcase pose is restored.
- **Inspection activity**: Pointer/touch dragging and independent keyboard-focused inspection. Both may be active together; return waits until both end.
- **Visible viewing time**: Time while the viewer is on-screen, the page is visible, and its window is active. Measure an inspection return by adding its visible portions before and after pauses. A regrab starts a new allowance only after all inspection ends again; reduced motion uses no animated return.
- **Carousel transition**: A visitor-requested change from the current model to the adjacent destination, with direction, movement, size change, and a completed or unavailable outcome. It is not automatic carousel playback.
- **Selection details and settlement**: The title, optional description, and accessible position message identify the centered model. Details are hidden while waiting; successful settlement makes the matching model and details available together.
- **Motion preference and visibility**: The visitor's reduced-motion preference and whether they are actively viewing the model; these govern automatic motion, not the availability of manual inspection or navigation.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: With normal motion and no inspection, a ready asymmetric model shows front, sides, rear, and front again in 24 seconds (±1 second) of visible viewing time. Time recognizable reference views externally at both acceptance widths and in all three modes; the model stays fully framed without zooming.
- **SC-002**: In five inspection/return cycles covering mixed-axis turns, complete revolutions, regrabs, and simultaneous pointer/keyboard inspection, control begins without a visible jump and return waits until both kinds of inspection end. Compare recognizable model landmarks with a captured reference view: both heading and tilt return within 1° of the original pose before spin resumes, with no extra full revolution. Externally time the visible return portions; their sum is at most 0.5 seconds per uninterrupted return, including a case hidden for longer than 0.5 seconds partway through. With reduced motion, the next visible update shows the saved pose without animated intermediate positions.
- **SC-003**: With three distinct models and their matching details supplied without a deliberately introduced loading delay, each Next/Previous activation reaches the centered destination at its normal fitted size with matching visible details within 0.5 seconds, measured externally from activation. Both directions and wrap boundaries show the specified sideways movement and perceptible shrinking/growing under normal motion. The chosen display mode is retained; a pause before movement counts toward this deadline.
- **SC-004**: Ten accepted next/previous activations with delayed completions end on the expected catalog entry with no late replacement. One deliberately unavailable destination shows an identified error, then browsing to a healthy entry succeeds without reloading the page.
- **SC-005**: With reduced motion enabled, observation shows no automatic spin or animated sideways movement, size change, or inspection return; manual full-turn inspection and next/previous still work. After all inspection ends, the next visible update shows the saved pose with no animated intermediate positions (0 ms animated duration). Enabling reduced motion during return does the same; enabling it during active inspection leaves the visitor in control until inspection ends. Other preference changes become visible by the next interaction or within 0.5 seconds while idle.
- **SC-006**: A keyboard-only visitor can enter, rotate, and leave the viewer and operate every mode/navigation control, with visible focus and no trap. After pointer-only inspection, release requires no extra click or focus change before return and resumed turntable motion. During simultaneous keyboard inspection and dragging, ending the drag alone produces no return or resumed spin; moving keyboard focus away while a drag continues also produces neither.
- **SC-007**: Compare the last view before hiding, scrolling out of sight, or switching windows with the first view on resuming: there is no skipped rotation or sudden return jump. After resizing between both acceptance widths and ten selection changes, models remain framed, controls remain reachable, there is no page-level horizontal scrolling, and abandoned gestures have no visible effect on a different selection. Leaving and revisiting the page never resumes an old drag.
- **SC-008**: An automated end-to-end acceptance exercise MUST deliberately delay availability of destination title/description for more than 0.5 seconds while testing navigation. Observe the displayed model, readable selection details, and accessible position messages: zero displayed images may pair a centered incoming model with readable predecessor details, no new successful-selection position message may appear while waiting, and exactly one current-selection position message must become available when the correct model and matching details settle together. Also prove actual eventual presentation of the distinct destination, not merely absence of mismatches. Cover ordinary Next/Previous, a delayed selection superseded by another request (including revisiting a model), and reduced motion. No particular test tool or application coordination mechanism is prescribed; this is required future acceptance, not an executed result.
- **SC-009**: With three distinct models, hold a noninitial model's load open and observe that all model loads have started and the initial model and matching details settle before that held load completes. Fail one noninitial model and verify that another healthy model is viewable without reloading and that selecting the failed model identifies it as unavailable.
- **SC-010**: At 375px and 1280px viewing widths, compare the carousel against Figma ProjectCarousel `39:205`: the canvas spans the carousel width behind usable navigation controls. At rest, only the selected model is drawn; during Next and Previous transitions, only the outgoing and incoming models are drawn, with the existing directional slide and scale preserved.

## Assumptions

- **Existing feature dependency**: Extend the implemented viewer/catalog in [feature 002](../002-gltf-model-carousel/spec.md). The directly implemented description, active-mode-arrow, and pointer-outline refinements are baseline behavior, not implementation tasks for this feature.
- **Explicit scope changes**: Automatic turntable replaces feature 002's static resting model. Directional slide/scale replaces abrupt selection changes and permits outgoing and incoming models to be visible together during movement. Hidden selection details replace visible outgoing title/description during loading. The 2026-10-30 amendment expands the canvas to the carousel width, adopts Figma ProjectCarousel `39:205`, and starts loading the whole catalog at startup; it does not change the specified motion or settlement behavior. Other baseline behavior remains intact; this specification does not itself change the running application.
- **Motion defaults**: One upright turn per approximately 24 seconds of visible viewing time. Inspection return takes at most 0.5 seconds of visible viewing time after all inspection ends, excluding pauses, or has 0 ms animated duration under reduced motion. Without an introduced loading delay, navigation settles within 0.5 seconds of activation. Deliberately delayed-loading cases are assessed for readable loading state, usable navigation, correct eventual settlement, and no mismatched details rather than the normal-navigation deadline. Exact movement shape and intermediate size remain planning choices, not observed Figma prototype timings.
- **Carousel interpretation**: This is a directional model-to-model transition inside the full-width carousel viewing area. Persistent smaller neighboring previews at rest, a navigable 3D ring, autoplay selection, swiping to select, zoom/pan, new lighting controls, and unrelated page redesign are not requested.
- **Product contract and planning boundary**: This specification requires observable motion, independent input behavior, hidden-while-waiting selection details, synchronized settlement, accessible position messages, and automated delayed-details acceptance. Planning chooses how to achieve those outcomes; earlier engineering prescriptions are not required solutions. No product ambiguity remains about the return target, combined input release, paused viewing time, reduced-motion restoration, or normal-navigation timing.
- **Assets and evidence**: Only owner-supplied work appears in the published portfolio. Verification-only models must not appear as portfolio projects. Supplied model files and authored textures remain unchanged. This file describes future acceptance scenarios, not executed motion verification.
- **Governance and workflow**: The installed constitution remains an unfilled template. No branch was created by specification. This visitor-facing revision replaces earlier technology-specific wording; review and reconcile the existing plan, contracts, validation guide, and task backlog before implementation without discarding the agreed observable behavior.
