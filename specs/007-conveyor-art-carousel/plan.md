# Implementation Plan: Conveyor Art Carousel

**Branch**: `007-conveyor-art-carousel` | **Date**: 2026-11-17 | **Spec**: [spec.md](spec.md)<br>
**Input**: `specs/007-conveyor-art-carousel/spec.md`

## Summary

Replace tilted, depth-offset Cover Flow with a horizontal conveyor. Keep three resting positions at shared depth/vertical center, with side models at 75% of center scale, and slide the row one slot per direction using a monotonic 700 ms easing curve. Models smoothly scale between center and side sizes during travel. Keep the current center turntable and inspection; neighbors remain at their authored default pose and can be cropped on narrow screens.

Separate retained artwork resources from visual belt instances so repeated artwork can occupy multiple slots without duplicate downloads, shared transforms, or double disposal. Replace loading supersession/movement lockout with a FIFO navigation queue. Preserve the renderer, readiness gates, final-draw/metadata transaction, display modes, and production isolation of acceptance hooks.

Implementation and subsequent edge-dither/side-scale updates are in place. See `quickstart.md` for verification results and outstanding full-suite issues.

**Target Platform**: Current browser portfolio with WebGL2, pointer/touch and keyboard input, reduced motion and visibility-aware rendering.<br>
**Project Type**: Client-rendered web application with one persistent art-viewer renderer.<br>
**Performance Goals**: 700 ms nominal monotonic slide; 1500 ms service-to-settlement budget with the current 175 ms final-presentation reserve and readiness safeguards; smooth frame pacing without animation in React state.<br>
**Constraints**: Queue waiting is excluded from the service budget. Independent loads stay retained; shared geometry/material/texture ownership stays per artwork. Three visible rest instances and at most four planned transition instances, even with two/three logical artworks. Preserve full-width canvas, root zoom compensation, DPR ≤2, and transparent background.<br>
**Scale/Scope**: 3D Art Carousel only; existing catalog scale and source assets unchanged. Game showcase, skills conveyor, background effect, typography, palette, and controls artwork are out of scope.

## Visual Direction

Preserve the portfolio's blue ASCII background, light outlined control artwork, local paper-bar highlights, title/caption styling, and current mode controls. The deliberate change is large, equally weighted artwork passing on a level belt, not new chrome, literal conveyor machinery, rails, panels, or decoration.

```text
Desktop:   [ previous ]     [ selected ]     [ next ]
                                 title
                            mode controls

Mobile:    [ prev…   |      selected      |   …next ]
                         title / controls

Next:       ← whole row, one slot
Previous:   → whole row, one slot
```

All slots share one depth; side models use 75% of the center's normalized scale. Keep the center at its existing projected resting size; retain the current spacing and edge crop. During navigation, center-to-side scale changes smoothly with horizontal position. No motion-driven whole-object fade, depth arc or tilted line accompanies travel. A stationary spatial dither mask fades fragments near both visible horizontal edges; even ambient/directional lighting replaces the earlier spotlight appearance.

## Implementation Approach

### 1. Separate artwork resources from belt instances

- Keep `catalog` keyed by artwork ID and retain one fetch/parse/resource tracker per artwork, including current embedded-resource validation and generation guards.
- Move slot presentation, inspection rotation, and visual-instance identity out of the assumption that one `LoadContext` owns exactly one visible group. Maintain an active-center instance reference separately from its logical asset.
- Build each occurrence from the centered, normalized, authored-roll-preserving hierarchy. Use `SkeletonUtils.clone` for independent scene hierarchies, including skinned models; share geometry, materials, and textures. Track clone-owned skeletons/bone textures separately from asset-owned resources.
- At rest, assign logical artwork at offsets -1/0/+1 using modulo indexing. For one artwork, create only the center. For two artworks, the left and right occurrences share artwork identity, not transform/pose identity.
- Reuse/pool occurrences where possible. Keep three rest occurrences and at most four live transition occurrences. Do not clone a whole catalog eagerly or clone hierarchy every animation frame.
- Retain per-artwork/per-mode preflight with the same renderer/offscreen target. Ensure new instance setup cannot bypass candidate validation and combined-draw recovery still isolates the failing artwork. Do not let one failed preview instance retire healthy instances of another artwork.
- No per-instance whole-object dither fade: edge entry/exit uses a screen-space ordered-dither mask followed by clipping. Shared materials receive common edge uniforms so repeated occurrences fade by fragment position without conflicting material state. Retained artwork-readiness fade combines with the spatial edge mask; offscreen preflight temporarily disables the edge mask.

### 2. Define one horizontal coordinate model

For service starting at logical index `s`, normalized slot coordinate `q`, spacing `D`, center scale `S`, side scale `0.75S`, and eased progress `e`:

- Next: initial coordinates `q = [-1, 0, 1, 2]`, artwork `mod(s + q, count)`, position `x = (q - e) * D`.
- Previous: initial coordinates `q = [-2, -1, 0, 1]`, same artwork mapping, position `x = (q + e) * D`.
- Every occurrence has `y = 0`, `z = 0`. At normalized position `p = q ± e`, scale is `0.75S + 0.25S * (1 - min(1, abs(p)))`. The center has scale `S`; side and outer slots have scale `0.75S`.
- At settlement, drop/recycle the occurrence outside the new resting range and rebase the remaining coordinate labels without changing their visible transforms.
- For missing/failed preview assets, keep corresponding slots empty and keep physical spacing. Snapshot participants once motion starts; a late preview may join at rest, not pop into the moving row.
- Use a horizontal stage aperture to clip entering/exiting occurrences. Derive its projected bounds from three slots and available body width so discarded occurrences are outside the aperture before recycling, even on wide screens. Preserve the full-width DOM canvas and stage-relative camera size compensation. Clear the full transparent canvas before the scissored visible draw to avoid trails when the aperture changes; save/restore scissor state during offscreen validation.
- Remove orbital depth placement, Z-axis tilt, two-/three-entry rear routes and orbit-specific camera depth inflation. Recompute camera near/far from common-depth model bounds so inspected poses remain unclipped.
- Rename internal orbit controls to belt spacing. Introduce a canonical `beltSpacing`/CSS `--carousel-belt-spacing` control and retain `orbitRadius`, `setOrbitRadius`, `getOrbitRadius`, `--orbit-radius`, and `--carousel-orbit-radius` as deprecated spacing aliases for this change, without triggering a renderer remount for runtime updates. Precedence: valid canonical option, canonical CSS value, legacy option, `--orbit-radius`, `--carousel-orbit-radius`, default 1.0; all values must be finite and positive. Remove the stylesheet's legacy default so explicit legacy CSS aliases remain usable; the viewer supplies the 1.0 default when no valid value is configured. Document alias removal as future work, not part of this feature.

### 3. Simplify motion; preserve pose behavior

- Retain `easeInOutSmooth` for zero endpoint velocity/acceleration; clamp input to [0,1] and compute one monotonic eased progress. Nominal duration 700 ms.
- Delete anticipation/overshoot phase calculations and their obsolete tunables. Keep deadline-aware shortening and final presentation reserve.
- Freeze the outgoing center's inspection snapshot, then interpolate its pitch/yaw to default using the existing per-axis shortest-path helper. Other occurrences remain at default pose. Repeated instances of the same artwork must not share this pose mutation.
- Promote the arrived center occurrence atomically, reset its inspection state, and resume the existing 24-second positive-yaw turntable only when ready/eligible. Keep 350 ms returns, regrab targets, separate inspection tokens, and visibility-aware animation time.
- Raycast visible occurrences, then require the hit occurrence to be the active center. Comparing only artwork ID is invalid when neighbors repeat the same artwork. Empty-stage pointer behavior and keyboard focus remain as currently defined.
- Resize recomputes spacing/aperture and instance transforms from unchanged normalized progress, not by restarting movement. Hidden/offscreen/unfocused viewers pause visual time without draining the queue.
- Reduced motion uses the same readiness/finalization path with no intermediate belt frames or automatic turntable. Preserve deliberate user inspection.

### 4. Add serial FIFO navigation in ProjectCarousel

- Native button activation captures a lightweight `{sequence, direction, enqueuedAtMs}` record in a ref-owned FIFO. Do not increment selection or curtain metadata at enqueue time for a request still waiting.
- If idle/ready, dispatch immediately. Initial model preparation counts as active service, so activations during initial loading queue until it resolves. Otherwise leave navigation buttons activatable for multi-artwork catalogs: remove the old moving-phase click rejection and moving-only `aria-disabled`. Keep actual disabled state for zero/one artwork.
- On dispatch, resolve direction against the current logical selected index, issue the next monotonically increasing viewer request ID, set service start time, curtain the destination, and execute the existing controller/metadata ticket handshake.
- Preserve original native activation timestamp separately from service start. The deadline uses native activation +1500 ms for an idle activation and service start +1500 ms for an entry that waited in FIFO; acceptance captures both queue delay and service latency so a long queue cannot be misreported as instant activation-to-presentation.
- Start the following request on a subsequent animation frame after successful `ready` reporting, not synchronously inside `finalize` or a microtask that could curtain the just-settled selection before presentation. Guard scheduled work with component lifetime/request identity.
- Recoverable selection errors release the queue after the existing error selection is established. Resolve subsequent directions from that logical error index, preserving onward navigation; if no healthy outgoing center is available, reuse the existing non-animated ready/error path rather than invent a belt arc.
- Terminal context loss/unavailable UI clears pending animation queue work; future activations retain existing unavailable-navigation behavior. Unmount clears queue and scheduled callbacks. Never recursively drain a long reduced-motion/error queue on one call stack.
- Queue state is transient control data, not per-frame React animation state. No cancellation, merging, artificial queue cap, or new queue-status UI in this feature.

### 5. Preserve synchronized presentation

Keep the existing candidate-preflight → metadata-proof → final centered draw → synchronous `finalize(ticket)` → `ready`/single position update sequence. Earlier queued destinations settle normally before the next service begins. Do not expose later queued details through title/caption DOM, `aria-hidden`, or `inert` early.

Retain request-generation checks even though dispatch becomes serial: canceled/late asynchronous loads, error recovery, unmount, and context loss can still invalidate work. Validate mode changes against the destination instance and preserve `scene.overrideMaterial` rather than rewriting authored mesh materials.

### 6. Update acceptance coverage, not just screenshots

- Extend acceptance-only presentation samples with unique instance ID, logical model ID, slot coordinate, service/queue timing, per-instance scale, and optional aperture bounds. Duplicate model IDs are expected; duplicate instance IDs are not.
- Replace orbital and right-only two-entry assertions in existing stage tests. Preserve unrelated readiness, disposal, metadata and display-mode assertions.
- Replace obsolete supersession/ignored-click expectations with FIFO ordering, including queued input during delayed preparation, alternating directions, reduced motion, failure recovery and unmount.
- Prove horizontal monotonic movement, common depth/height, smooth monotonic center/side scaling, signed one-slot displacement, repeat-safe center hit testing, offscreen recycling, no duplicate downloads, and bounded instance count.
- Keep native activation/compositor timing instrumentation; add queue-wait and service timing instead of redefining the native event timestamp.
- Retain distinct textured test assets outside `glb/`. Cover a skinned hierarchy with a minimal acceptance-only fixture if existing assets cannot exercise clone ownership. Production must still exclude all acceptance entries, fixtures and instrumentation branches.
